# 直播间重设计方案

> 版本：2026-11-09  
> 状态：待确认 → 执行

---

## 一、设计理念

**直播间是主界面，永远在线。** 不存在"开播"动作，页面打开即是聊天窗口，主播默认选中，模式默认实时对话。所有配置以小图标分布在窗口四周，轻触即开、用完即收。

## 五、操作链条分析与评估

### 场景 A：首次使用，想直接和主播聊（实时对话）

**操作链：**
1. 打开页面 → 看到空聊天窗口，顶部显示"（无主播）"
2. 点顶部主播名 → 下拉提示「还没有主播，点击新建」→ 点击
3. 进入主播管理弹窗 → 输入名称 → 保存
4. 自动选中新主播，返回聊天窗口
5. 底部输入弹幕 → 发送 → 主播回复

**问题：** 步骤3还需要配置"回复配置"（绑定模型），否则无法回复  
**优化：** 首次新建主播时，检测是否有可用配置 → 没有则在主播管理弹窗内嵌入一步「快速配置模型」引导（只需选 provider + model，其他用默认值），完成后直接回到聊天窗口  
**优化后链条：** 打开 → 新建主播 → (内嵌)选模型 → 发弹幕聊天，4步

---

### 场景 B：日常使用，换个主播继续聊（实时切换）

**操作链：**
1. 点顶部主播头像/名字
2. 下拉选择另一个主播
3. 聊天窗口保留消息历史，新主播接管

**评估：** ✅ 2步，体验流畅。  
**注意：** 切换时显示「主播已切换为花花」的短暂 toast 提示，避免用户不知道是否生效。

---

### 场景 C：用剧本跑测试

**操作链：**
1. 点左侧 📜 剧本图标 → 剧本面板滑出
2. 选择一个剧本，点「▶ 加载」
3. 面板自动关闭，聊天窗口开始播放剧本
4. 底部出现控制条（节奏 / 下一步 / 停止）

**问题：** 如果当前是实时对话模式，加载剧本是否自动切换模式？  
**结论：** 是，加载剧本 = 隐式切换到 script 模式（行为一致，用户不用手动切）

**优化：** 剧本面板内预览条数和时长，让用户对剧本有感知再决定加载，不是盲选。  
**评估：** ✅ 4步，合理。

---

### 场景 D：导入历史记录并进行逐句评估

**操作链：**
1. 点右侧 📥 导入图标 → 导入面板滑出
2. 拖入/选择 .md 文件
3. 角色分配（拖拽列表，主播唯一校验）
4. 勾选「导入后进行逐句评估」，选择评分标准
5. 点「确认导入」
6. 面板关闭，聊天窗口展示历史记录（只读），右侧🎯评分图标显示进度

**问题：** 角色分配步骤中，用户可能不熟悉"角色"概念  
**优化：** 角色选项文案改为「主播（被评估方）/ 观众（提问方）/ 忽略」，并在面板顶部显示「主播：谁的回复会被分析和评估」的单行说明

**评估：** ✅ 5步，不算冗长，关键步骤有价值。

---

### 场景 E：查看历史场次，继续对话

**操作链：**
1. 点右侧 📊 场次库图标
2. 选择一个历史会话
3. 聊天窗口展示该会话记录（只读模式）
4. 点底部「继续对话」按钮（或底部输入条提示）
5. 切换到实时模式，在历史记录基础上继续

**后端影响：** `startSim({ mode: 'live', anchorName, configId })` 的上下文只读取当前 active session 的消息历史。需要后端新增接口：`POST /sims` 支持传入 `resumeSessionId`，让 engine 把历史记录作为初始 context 注入。

**评估：** ✅ 5步，「继续对话」按钮降低认知负担，体验自然。

---

### 场景 F：调整回复配置（换模型）

**操作链：**
1. 点右侧 ⚙️ 配置图标
2. 面板打开，显示当前配置
3. 改模型/温度
4. 点保存 → 当前直播间立即生效

**问题：** "立即生效"是指下一条弹幕开始用新配置，还是需要 stop+start？  
**结论（方案A）：** 需要 stop+start。做法：保存配置后，如果当前有 active session，提示「配置已更新，需要重新开播才能生效」+ 「立即重开直播」按钮。不强制，用户可以在下一次自然结束后再开。

**评估：** ✅ 3步主流程，重开直播是可选操作，体验可接受。

### 场景 G：编辑主播人设

**操作链：**

2. 主播管理弹窗（全屏 Dialog）打开

## 六、技术实现方案

### 6.1 "房间永远在线"的状态管理（前端方案A）

```
RoomStore（Zustand 或 context）：
  activeSessionId: string | null    // 当前 active sim session
  anchorName: string | null         // 当前选中主播（持久化）
  configId: string | null           // 当前选中配置（持久化）
  mode: 'live' | 'script'           // 当前模式（持久化）
  scriptId: string | null           // 当前剧本（持久化）
  viewingSessionId: string | null   // 只读查看的历史会话（独立于active）
  isReadOnly: boolean               // 当前是否为查看模式
```

页面挂载时：
1. 查询 `GET /sims`，检查是否有 running 的 session 属于当前 anchorName + configId
2. 有 → 自动恢复（subscribe 该 sessionId）
3. 无 → 维持空房间（不自动开播，等用户第一次发弹幕时隐式触发 startSim）

"隐式开播"：
- 用户点发送弹幕时，如果没有 active session，先调 `startSim` 创建，成功后再注入弹幕
- 这样用户完全感知不到"开播"这个动作

### 6.2 实时切换主播

```
async switchAnchor(newAnchorName: string) {
  if (activeSessionId) {
    await api.stopSim(activeSessionId)     // stop 旧session
  }
  setAnchorName(newAnchorName)
  setActiveSessionId(null)                 // 下次发弹幕时隐式startSim
  // 消息列表保留在前端，不清空（视觉上无断层）
}
```

### 6.3 历史记录衔接（新增后端接口）

```
POST /sims
{
  mode: 'live',
  anchorName: 'xxx',
  configId: 'yyy',
  resumeSessionId: 'zzz'   // 新增可选字段，把历史记录注入初始 context
}
```

后端 `engine.ts` 在初始化时，如果有 `resumeSessionId`，从 DB 读取该会话的消息记录，转为 `AnchorExchange[]` 作为初始 history 注入。

### 6.4 路由结构

```
/              → LiveRoom（新主页面，全屏聊天）
/evals         → EvalsPage
/rubrics       → RubricsPage
/settings      → ProvidersPage
```

RoomPage（现有 `/room` 子路由结构）移除，所有功能收入 LiveRoom 的面板中。

### 6.5 组件迁移映射

| 现有组件 | 迁移去向 |
|---------|---------|
| `StartPanel` | 拆解消失，状态分散到 RoomStore + 顶部条 + 配置面板 |
| `RunningList` | 不再需要（一次只有一个 active session） |
| `RunView` 消息列表部分 | 提取为独立 `ChatArea` 组件（LiveRoom 的核心） |
| `RunView` 控制条部分 | 提取为底部 `ScriptControlBar`（仅 script 模式显示） |
| `RunView` 弹幕输入 | 提取为底部 `DanmakuInput` 组件 |
| `ImportPanel` | 原样移入 ImportSheet 面板 |
| `ScriptsPage` | 编辑器部分移入 ScriptDialog（全屏）；选择部分移入 ScriptSheet 面板 |
| `AnchorsPage` 主播 | 移入 AnchorDialog（全屏）|
| `AnchorsPage` 配置 | 移入 ConfigSheet 面板（带 TrialPanel）|
| `TranscriptsPage` | 移入 SessionSheet 面板 |
| `SessionView` | 原样复用 |
| `MessageBubble` | 原样复用 |

## 七、执行阶段划分

### Phase 1：LiveRoom 骨架（前端重构，无后端改动）

- 新建 `LiveRoom.tsx`（替换 `RoomPage.tsx`）
- 实现顶部房间条（主播切换下拉 + 模式切换）
- 实现左右图标列（图标 + Tooltip）
- 实现 ChatArea（消息列表，从 RunView 提取）
- 实现底部 DanmakuInput
- 实现 ScriptControlBar（script 模式条件展示）
- 路由指向 LiveRoom

### Phase 2：各功能面板（Sheet/Dialog 化）

- ScriptSheet + ScriptDialog（剧本选择 + 全屏编辑器）
- ImportSheet（导入，含评估选项）
- SessionSheet（场次库）
- ConfigSheet（配置 + 试播）
- AnchorDialog（主播管理，全屏）

### Phase 3：状态管理与"房间永远在线"

- 实现 RoomStore（anchorName/configId/mode 持久化）
