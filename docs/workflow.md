# 开发工作流

## 一个模块一个 session

1. 新 session 开头：先读 `README.md`（进度清单）和 `docs/`，再看 `git log` 了解最近做了什么。只读和本次任务相关的代码。
2. 做完一个模块：测试、类型检查、构建都通过，浏览器实测走通后，提交并推送。
3. 收尾：把本次定下的设计和规则写进 `docs/requirements.md` / `docs/architecture.md`，并更新 README 进度清单。决策只写在对话里，新 session 就看不到。
4. 然后开新 session 做下一个模块。只有在修刚做完的模块或小改时，才在原 session 里继续。

新 session 开头可以这样说：

> 先读 README 和 docs，了解项目现状。这次要做：<模块>。

## 控制上下文

- 不要整段粘贴大文件或长日志，给出路径，让 agent 按需读取。
- 需要通读很多文件的排查交给子任务，只把结论带回主对话。
- 一个模块对应一个提交，提交说明写清楚做了什么。
