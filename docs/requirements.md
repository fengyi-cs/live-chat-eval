# 需求说明 v1.1

> 本文是需求与已定规则的准绡。对话里定下的规则要写到这里，见 [workflow.md](workflow.md)。

直播间 AI 主播对话评估框架。现阶段纯文字，不接数字人与 TTS；目标是先把框架搭出来，评分规则后续再细调。

## 1. 聊天记录导入

### 1.1 格式

```
# <主播名> 聊天记录

- 场次 ID：1366
- 主播：阿灵（A065）
- 开始时间：2026/10/27 17:53:55
- 结束时间：2026/10/27 18:30:56

## 对话记录

### 2026/10/27 17:54:11｜卡文

正文（单段）
```

- 发言人 `自动动作` 的正文形如 `（动作）鼓了下脸`，表示数字人动作，不是发言。
- 样例见 `fixtures/transcripts/`（已脱敏）。真实记录不进仓库。

### 1.2 解析与角色确认

1. 解析出所有发言人及发言条数。
2. 用户为每个发言人指定角色：主播 / 观众 / 动作 / 忽略。
   - 发言人名与已存主播档案匹配，或与元信息中的主播名一致 → 默认"主播"。
   - `自动动作` → 默认"动作"。
3. 确认后持久化。之后导入同一主播的文档自动识别，可直接评估。

### 1.3 主播档案

- 以**主播名字**为主键（名字不重复），元信息中的编号只作为附带信息保存。

### 1.4 回复配对

- 一条主播发言关联"上一条主播发言之后、它之前"的全部观众弹幕。
- 响应延迟 = 主播发言时间 − 最早一条关联弹幕的时间。
- 无关联弹幕的主播发言标为**主动发言**，不按"是否回应弹幕"评分。
- 动作事件挂到它之前最近的那条主播发言上；只存储与展示，后续用于驱动数字人。

### 1.5 其他

- 以场次 ID 去重，支持批量导入，导入后可直接发起评估。

## 2. 模拟运行

- **单人模拟**：页面手动发弹幕，与 AI 主播实时对话。
- **多人剧本**：多个虚拟用户（昵称、画像），每人 n 条有序弹幕，每条带时间偏移。
- 回放模式：实时 1x / 2x / 5x / 10x / 跳过等待 / 单步，开播后可切换。
- 模拟会话与导入记录同一数据结构、同一评估流程。导出为 1.1 的 md 格式**尚未实现**。

### 2.1 弹幕剧本格式

每行一条：`[时间] 昵称：内容`。

- 时间写法：`0:05`、`1:02:03`、`12s` 表示从开播算起；`+2` 表示比上一行晚 2 秒。
- 不写时间：按「默认间隔」接在上一行后面；第一行是 0 秒。
- `#` 开头的行是注释。解析后按时间稳定排序，格式有误时报出行号。

### 2.2 计时规则

- 延迟 = 主播回复完成时间 − 最早一条被回应弹幕的到达时间。含义与 1.4 导入记录一致，两边可以直接比较。
- 生成期间到达的弹幕，等这次回复完成后再处理；在记录里排在这次回复前面。
- 被策略跳过的弹幕记为未回应。
- 主播生成中点「结束直播」，没生成完的回复会被丢弃。
- 服务重启后，进行中的模拟标为「已停止 · 服务重启，模拟被中断」。

## 3. AI 主播

- **人设**：支持上传人设 prompt 文件，也支持在线编辑。
- **回复策略**：可插拔接口，内置一套可调参数，例如：
  - 合并时间窗口（秒）、单次最多回应弹幕数
  - 冷场多久触发主动发言
  - 优先级规则（礼物 / 提问 / @主播 / 新用户）与权重
  - 是否启用 LLM 判断回复哪些弹幕
- 内置策略：逐条回复、时间窗口合并（超出上限时回应最新的几条）、优先级筛选（按权重打分挑选）。所有回复都受最小回复间隔约束。
- 「让模型判断回应哪几条」：多调用一次模型，从候选弹幕里挑出最多「单次最多回应」条，耗时计入延迟；输出解析不了时退回规则选择并给出警告。
- 试播是手动触发，不受策略影响；策略只在直播间模拟中生效。
- 预留外部适配器，后续对接公司已有回复逻辑。

## 4. 模型接入（主播与裁判共用）

- 自定义服务商：`base_url`、`api_key`、类型。
- 类型按地址自动识别（OpenAI 兼容 / Anthropic / Gemini / Ollama），可手动覆盖。
- 自动拉取模型列表、选择模型、测试对话，支持流式输出。
- 预留"公司自有大脑"适配位。
- 裁判模型复用这套接入；打分策略由框架内置。

## 5. 评估

### 5.1 规则基础分（不调用模型，每项 0-100）

| 规则 | 默认参数 | 默认权重 |
|---|---|---|
| 响应延迟 | ≤ 3 秒满分，≥ 15 秒 0 分，中间线性；主动发言不计 | 1 |
| 漏回率 | (1 − 未回应弹幕 / 观众弹幕) × 100 | 1 |
| 回复长度 | 6-80 字满分，过短按比例、过长按超出比例扣分 | 1 |
| 重复度 | 和前 5 条主播发言按字二元组算 Dice 相似度，(1 − 最大相似度) × 100 | 1 |
| AI 腔词库 | 每命中一个词扣 25 分，词库可编辑 | 2 |

各项先逐条计算再取平均，按权重合成规则分。

### 5.2 LLM 裁判维度（1-5 分，每档有描述）

| 维度 | 粒度 | 默认权重 |
|---|---|---|
| 去 AI 味 / 口语化（核心） | 逐条 | 3 |
| 回应与逻辑（主动发言时不评） | 逐条 | 2 |
| 趣味性 | 逐条 | 1.5 |
| 人设一致性 | 逐条 | 2 |
| 性格遵从 | 逐条 | 1 |
| 整场一致性 | 整场 | 2 |
| 互动节奏 | 整场 | 1 |

- 逐条维度评每句主播发言。裁判能看到人设、之前最近 10 条对话、这句回应的弹幕和发言本身。整场维度看完整场记录评一次，过长时保留最近约 12000 字。
- 维度可以增删，名称、权重、说明和 1-5 分各档描述都能改，会原样写进裁判提示词。维度键只用小写字母、数字和下划线。
- 裁判只输出 JSON。解析失败时把错误告诉模型重试，默认最多 3 次；仍然失败的条目标为「打分失败」，不计入汇总。可以设置每条打分 1-3 次取平均。

### 5.3 汇总

- 每个维度取适用条目的平均分，换算为 0-100（(分 − 1) / 4 × 100），再按权重合成 LLM 分。
- 综合指数 = 规则分 × 30 + LLM 分 × 70（除以权重和），比例可以改。只有一边有分时取那一边。
- 评估保存当时的模板快照。编辑或删除模板不影响已有报告。
- 没有启用 LLM 维度的模板不调用模型，综合指数就是规则分。
- 上述默认值是初稿，待用真实模型和真实记录校准。

### 5.4 尚未实现

- 对比实验（同一剧本 × 多套主播配置并排比较）。数据结构已预留。

## 6. 非功能

- 只做 Web，响应式；本地个人使用；无登录、无用户系统。
- 状态本地持久化（SQLite 单文件，`data/` 不进 git）；API key 本地明文存储。
- 克隆后一条命令启动。
- GitHub 私有仓库。
