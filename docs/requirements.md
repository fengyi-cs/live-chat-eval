# 需求说明 v1.0

直播间 AI 主播对话评估框架。现阶段纯文字，不接数字人与 TTS；目标是先把框架搭出来，评分规则后续再细调。

## 1. 聊天记录导入

### 1.1 格式

```
# <主播名> 聊天记录

- 场次 ID：1366
- 主播：阿灵（A065）
- 开始时间：2026/10/27 17:53:55
- 结束时间：2026/10/27 18:30:56

## 对话记录

### 2026/10/27 17:54:11｜卡文

正文（单段）
```

- 发言人 `自动动作` 的正文形如 `（动作）鼓了下脸`，表示数字人动作，不是发言。
- 样例见 `fixtures/transcripts/`（已脱敏）。真实记录不进仓库。

### 1.2 解析与角色确认

1. 解析出所有发言人及发言条数。
2. 用户为每个发言人指定角色：主播 / 观众 / 动作 / 忽略。
   - 发言人名与已存主播档案匹配，或与元信息中的主播名一致 → 默认"主播"。
   - `自动动作` → 默认"动作"。
3. 确认后持久化。之后导入同一主播的文档自动识别，可直接评估。

### 1.3 主播档案

- 以**主播名字**为主键（名字不重复），元信息中的编号只作为附带信息保存。

### 1.4 回复配对

- 一条主播发言关联"上一条主播发言之后、它之前"的全部观众弹幕。
- 响应延迟 = 主播发言时间 − 最早一条关联弹幕的时间。
- 无关联弹幕的主播发言标为**主动发言**，不按"是否回应弹幕"评分。
- 动作事件挂到它之前最近的那条主播发言上；只存储与展示，后续用于驱动数字人。

### 1.5 其他

- 以场次 ID 去重，支持批量导入，导入后可直接发起评估。

## 2. 模拟运行

- **单人模拟**：页面手动发弹幕，与 AI 主播实时对话。
- **多人剧本**：多个虚拟用户（昵称、画像），每人 n 条有序弹幕，每条带时间偏移。
- 回放模式：实时 / 加速 / 单步。
- 模拟会话与导入记录同一数据结构、同一评估流程；可导出为 1.1 的 md 格式。

## 3. AI 主播

- **人设**：支持上传人设 prompt 文件，也支持在线编辑。
- **回复策略**：可插拔接口，内置一套可调参数，例如：
  - 合并时间窗口（秒）、单次最多回应弹幕数
  - 冷场多久触发主动发言
  - 优先级规则（礼物 / 提问 / @主播 / 新用户）与权重
  - 是否启用 LLM 判断回复哪些弹幕
- 内置策略：逐条回复、时间窗口合并、优先级筛选、LLM 判断。
- 预留外部适配器，后续对接公司已有回复逻辑。

## 4. 模型接入（主播与裁判共用）

- 自定义服务商：`base_url`、`api_key`、类型。
- 类型按地址自动识别（OpenAI 兼容 / Anthropic / Gemini / Ollama），可手动覆盖。
- 自动拉取模型列表、选择模型、测试对话，支持流式输出。
- 预留"公司自有大脑"适配位。
- 裁判模型复用这套接入；打分策略由框架内置。

## 5. 评估

- **规则基础分**：响应延迟、回复长度、漏回率、重复度、AI 腔 / 书面语词库命中等可计算指标。
- **LLM 裁判分**：
  - 内置默认维度，核心是"去 AI 味 / 口语化"（越像真人口语分越高），另有逻辑、趣味性、人设一致性、性格遵从。
  - 用户可新增维度、编辑细则与权重；维度动态注入裁判 prompt。
  - 评分模板可存多套；每次评估保存模板快照。
- **粒度**：逐条打分 → 汇总整场 → 再叠加一次整场维度评估。
- **分制**：维度 1-5 分（带锚点），每项附理由；综合指数加权换算为 0-100。
- 对比实验首版不做，数据模型按"会话/剧本 × 主播配置 × 运行"预留。

## 6. 非功能

- 只做 Web，响应式；本地个人使用；无登录、无用户系统。
- 状态本地持久化（SQLite 单文件，`data/` 不进 git）；API key 本地明文存储。
- 克隆后一条命令启动。
- GitHub 私有仓库。
